Made for local models

A small model on your own machine makes more mistakes than a frontier model. These tools are built so a mistake costs nothing: the tool does the careful part, and the model only has to follow the steps.

1Dry run by default

Every change is a preview unless the model asks for apply=true. It sees the exact plan, a field-by-field diff, warnings and the risk level. Nothing is sent.

2Two deliberate steps for risky changes

Critical changes need the confirm token from that dry run. It's tied to the exact plan and the device's current state, and it expires in 5 minutes.

3The tool checks its own work

After a change it reads the device back and reports applied, mismatch or no_effect. The model doesn't have to judge.

4Everything is undoable

Each change is journaled with the state before it. One call with the journal id puts it back.

5The tool remembers for the model

Every reply starts with a short memory: what the model was asked to do, what actually happened, and whether it is done. Small models lose their plan between turns; the tool does not.

It always says what's next

Replies carry a next step, and errors come with a hint and the tools that do work. A small model never has to guess.

One tool per area

Related actions share one tool instead of hundreds of tiny ones. The full router set is about 11k tokens, so give the model a 16k+ context.

Secrets stay out of the chat

Passwords are masked in every reply and read from files, never passed as arguments.

Watch it work

Every error, refusal, verified change and firmware update goes to a local log you can follow live in a window. Field reports to us are off until you choose.
